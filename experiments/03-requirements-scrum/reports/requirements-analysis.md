# 实验三：Teedy 软件需求分析报告

> 学号：1260101027；姓名：汤鑫。
> 本报告基于 Teedy 真实源码结构（REST 资源层、DAO、前端控制器）与实际功能分析，不编造功能。

## 1. 项目简介

Teedy 是一款开源的轻量级文档管理系统（Document Management System, DMS），上游为 `sismics/docs`。它提供文档的上传、存储、检索、版本管理、权限控制与工作流审批等能力，可作为中小团队的知识管理与文档协作平台。

- 技术栈：后端 Java（JAX-RS / Jakarta REST），前端 AngularJS + Bootstrap，持久化 JPA（H2/PostgreSQL），全文检索基于 Lucene/Elasticsearch 类索引，构建工具 Maven。

## 2. 功能性需求

通过对源码的功能域分析（REST 资源类 + 前端控制器），Teedy 的功能性需求如下：

| 编号 | 功能域 | 需求描述 | 源码依据 |
| --- | --- | --- | --- |
| FR-1 | 文档管理 | 创建、编辑、查看、删除文档，支持标题、描述、语言等元信息 | `DocumentResource`（GET/POST/PUT/DELETE `/document`） |
| FR-2 | 文件上传与版本 | 上传文件、查看历史版本、文件重命名、附件管理 | `FileResource`（PUT、`/versions`、`/attach`） |
| FR-3 | 文档检索 | 全文搜索，按标签、元数据、创建者、日期等条件筛选 | `DocumentDao`（`DocumentCriteria` 组合查询）、前端搜索 |
| FR-4 | 标签与分类 | 为文档打标签、管理标签、按标签浏览 | `TagResource`、`DocumentModalAddTag` |
| FR-5 | 元数据管理 | 自定义元数据字段，为文档附加结构化信息 | `MetadataResource`、`DocumentMetadataDao` |
| FR-6 | 权限控制 | 基于用户/组/ACL 的文档访问控制 | `AclResource`、`AclDao`、`AclType` |
| FR-7 | 工作流审批 | 定义审批流程（Route），文档流转与审批 | `RouteResource`、`RouteModelResource`、`RouteStep` |
| FR-8 | 文档共享 | 生成共享链接，控制公开访问 | `ShareResource` |
| FR-9 | 用户与组管理 | 用户注册/登录、分组、角色权限 | `UserResource`、`GroupResource` |
| FR-10 | 审计日志 | 记录文档操作、登录等审计轨迹 | `AuditLogResource`、`AuditLogType` |
| FR-11 | 文档关系 | 建立文档之间的关联关系 | `RelationDao`、`SelectRelation` |
| FR-12 | 评论协作 | 对文档添加评论 | `CommentDao`、`CommentResource` |
| FR-13 | 全文索引重建 | 文档内容索引与重建 | `RebuildIndexAsyncEvent`、`FileProcessingAsyncListener` |
| FR-14 | 系统配置与监控 | 系统参数、存储配额、监控 | `AppResource`、`SettingsMonitoring`、`ConfigDao` |

## 3. 非功能性需求

| 编号 | 类别 | 需求描述 |
| --- | --- | --- |
| NFR-1 | 性能 | 文档列表与全文检索在常规数据量下响应迅速（< 1s），支持异步文件处理避免阻塞 |
| NFR-2 | 可用性 | 提供 Web 界面，支持多语言（含简体中文），响应式布局适配移动端 |
| NFR-3 | 安全 | 支持密码加密存储、双因素认证（TOTP）、会话管理、ACL 权限隔离、审计日志 |
| NFR-4 | 可维护性 | 模块化 Maven 多模块架构（docs-core / docs-web / docs-web-common），前后端分离 |
| NFR-5 | 可扩展性 | 支持自定义元数据、Webhook、主题定制、LDAP 集成 |
| NFR-6 | 可部署性 | 支持原生部署与 Docker 容器化，可迁移 PostgreSQL |
| NFR-7 | 兼容性 | 支持常见文档格式（PDF、图片、Office 文档），集成 OCR 文字识别 |

## 4. 选定的三个主要功能

依据教材建议（文档上传、文档检索、文档管理）并结合真实源码，选定以下三个核心功能作为 Scrum 需求分解对象：

1. **文档上传与版本管理**（FR-2）
2. **文档检索**（FR-3）
3. **文档管理（含标签与权限）**（FR-1 + FR-4 + FR-6）

## 5. 用户故事（User Story）

采用「作为…，我想要…，以便…」格式。

### 5.1 文档上传与版本管理

- **US-1**：作为用户，我想要上传 PDF/图片/Office 文件到 Teedy，以便集中存储和归档文档。
- **US-2**：作为用户，我想要查看文件的历史版本，以便追溯文档的修改记录。
- **US-3**：作为用户，我想要上传同一文档的新版本，以便保持文档内容最新。
- **US-4**：作为用户，我想要重命名已上传的文件，以便文件命名清晰规范。

### 5.2 文档检索

- **US-5**：作为用户，我想要通过关键词全文搜索文档，以便快速定位所需内容。
- **US-6**：作为用户，我想要按标签筛选文档，以便按分类浏览。
- **US-7**：作为用户，我想要按创建者/日期等条件组合筛选，以便缩小检索范围。

### 5.3 文档管理（含标签与权限）

- **US-8**：作为用户，我想要创建和编辑文档（标题、描述），以便组织知识。
- **US-9**：作为用户，我想要为文档添加标签，以便分类管理。
- **US-10**：作为用户，我想要设置文档的访问权限（用户/组），以便控制谁能查看。
- **US-11**：作为管理员，我想要删除文档，以便清理过期内容。
